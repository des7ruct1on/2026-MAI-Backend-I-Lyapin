# Lesson 02 — nginx + gunicorn + WSGI

## Что сделано
- `myapp.py`: WSGI-приложение, которое генерирует пароль по правилам из задания и в конце делает `time.sleep(0.05)`.
- `nginx/nginx.conf`: конфиг с двумя важными location:
  - `location /public/` — отдаёт статику из папки `public/`
  - `location /gunicorn/` — проксирует запросы в gunicorn через `upstream`
- `public/example.txt`: пример файла в статике.
- `smoke_test.py`: локальная проверка, что пароли удовлетворяют требованиям.

## Требования из задания (чеклист)
- [x] nginx и gunicorn (в этой репе: конфиг + запуск gunicorn командой)
- [x] `location /public/` отдаёт статику из `public/`
- [x] WSGI-приложение генерирует пароли по правилам и делает `sleep(0.05)`
- [x] `location /gunicorn/` через `upstream` проксирует в WSGI (gunicorn)
- [ ] замеры производительности `ab`/`wrk` (в инструкции описано что именно мерить)

## Правила пароля (как в задании)
- длина от 8 до 16
- минимум 1 цифра, 1 буква в нижнем регистре, 1 буква в верхнем регистре
- минимум 1 символ из `#[]().,!@&^%*`

## Запуск WSGI через gunicorn
### Вариант A: просто проверить через gunicorn (рекомендуется)
1) Установить gunicorn (в активированном venv):

```bash
pip install gunicorn
```

2) Запустить (порт 8000, как в `nginx.conf`):

```bash
gunicorn --workers 4 --bind 127.0.0.1:8000 myapp:app
```

3) Проверить напрямую (без nginx) открыв в браузере/через HTTP-клиент:
- `http://127.0.0.1:8000/` (вернёт пароль)

Можно задавать диапазон длины параметрами:
- `?min=8&max=16`

### Вариант B: запуск через `run_app.sh` (Linux/macOS)
В папке есть `run_app.sh`, он запускает gunicorn с 4 воркерами.
На Windows проще использовать команду из варианта A.

## Настройка nginx
В `nginx/nginx.conf` используются плейсхолдеры `<path>`.
Их нужно заменить на абсолютный путь до папки `lesson-02`.

Пример:
- Linux: `<path>` → `/home/user/2026-MAI-Backend-I-Lyapin/lesson-02`
- Windows: `<path>` → `C:/Users/<you>/Desktop/.../2026-MAI-Backend-I-Lyapin/lesson-02`

После замены:
- `location /public/` будет смотреть в `<path>/public/`

## Проверка nginx
1) Положить любой файл (картинку/видео/текст) в `lesson-02/public/`.
2) Запустить nginx с этим конфигом.
3) Открыть в браузере:
- `http://localhost/public/<имя_файла>`

Проверка проксирования в gunicorn:
- `http://localhost/gunicorn/` (должен вернуть пароль)

## Измерение производительности (ab/wrk)
Нужно сделать 3 замера:
- **public**: `http://localhost/public/...`
- **gunicorn через nginx**: `http://localhost/gunicorn/`
- **напрямую gunicorn**: `http://127.0.0.1:8000/`

Подбор нагрузки: увеличивать rps до тех пор, пока при +10% начнут появляться таймауты/ошибки.

## Частые проблемы
- Если в браузере 502 на `/gunicorn/` — проверь что gunicorn запущен на `127.0.0.1:8000`.
- Если `/public/...` не открывается — проверь что `<path>` заменён на реальный абсолютный путь и файл реально лежит в `public/`.
